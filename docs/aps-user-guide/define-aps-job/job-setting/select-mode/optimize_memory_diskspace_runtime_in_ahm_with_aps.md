---
title: The use of individual ERTBOX per zone
---

When APS is used in a workflow with assisted history matching (AHM) in ERT and gaussian field parameters generated by APS is updated, APS and ERT use a help grid called ERTBOX grid. There are several reason for using this help grid:

- A geomodel often contains multiple zones with different facies distribution and will need field parameters like the Gaussian fields for APS that is defined in different ways for each zone.
- The number of grid layers may vary from zone to zone, hence the size of the field parameters will vary from zone to zone.
- The number of grid layers may vary from realization to realization due to structural model uncertainty that is the basis for the geomodel grid geometry.
- By using the ERTBOX help grid with fixed size (not varying from realization to realization), it is possible to use the grid index as label for each field parameter value when calculating statistical estimates of mean, standard deviation, covariances etc that is necessary for the update algorithm in ERT.
- The ERTBOX grid must be located laterally in the same location as the geomodel grid. Since the ERTBOX grid is a regularly spaced and orthogonal grid and the geomodel grid does not always have to look regular in map view, it is not always possible to align the ERTBOX grid perfectly in map view with the geomodel grid. But it should have the same number of grid cells in the local x and y direction as the geomodel grid. In ERT when running the update algorithm with Ensemble Smoother Multiple Data assimilation (ES-MDA) with 'Distance-based localization' ERT will calculate distances from location of observations to location of a field parameter value (grid cell center point), and the location of the grid cell center points in the ERTBOX grid is used in that context. For other update modes in ERT without distance-based localization, only the size (nx, ny, nz) of the field parameters are used and then it is not so important if the ERTBOX grid is not aligned with the geomodel grid, but also in this case it is most optimal to have approximately the same lateral size of the grid cells in the ERTBOX as in the geomodel grid due to variogram settings in APS.

A description of how to specify the ERTBOX grid is found in 'FMU assisted history matching mode' section.

A geomodel where APS is used for multiple zones, will use the same ERTBOX grid for all zones. This means that a geomodel zone with 50 layers and a geomodel zone with 5 layers will use the same ERTBOX grid size. The ERTBOX size will then have at least 50 layers to be able to contain both field parameters (but of course one at a time). All field parameters (the gaussian fields from APS) will use the same size of ERTBOX grid. This means there will be lots of grid cell values that are updated by ERT, but not used in APS since many of the grid cells in the ERTBOX does not correspond to any active grid cell in the geomodel grid. This will not be optimal when it comes to the use of disk space, memory use in ERT and computation time for updates in ERT.

A more optimal strategy is to avoid having to use the same ERTBOX grid for all zones, but instead define one ERTBOX per zone and ensure that the number of grid layers in the ERTBOX grid is sufficient to contain the field parameters for the zone.  In the example above with one zone in the geomodel using 50 layers and another zone using 5 layers, we could define one ERTBOX grid with at least 50 layers and one with at least 5 layers. In ERT it is now possible to specify an individual ERTBOX grid per field parameter as an option instead of using one common ERTBOX grid.  To benefit from this, the proposed workflow below can be used with APS in RMS:

* A multizone grid is split into multiple single zone grids
* A separate ERTBOX grid is defined for each of the single zone grids.
* An APS job is specified for each of the single zone grids and the ERTBOX grid associated with the single zone grid is used in the assisted history match mode in APS.

Example of this method is the open source synthetic FMU (Fast Model Update) project, called Drogon. Here the geomodel grid consists of three zones, and a single zone grid is defined per zone, and a separate APS job is also defined for each of the single zone grids. The size of the three zones vary from 15 to 50 layers, and significant disk space is saved when using individually size ERTBOX grids for each zone when running many realizations in the FMU project.

Note that number of grid layers of the ERTBOX grid corresponding to a geomodel zone must be at least as large as the maximum number of layers that may appear in the realizations for that zone. Geomodel grid with zones that are defined with proportional grid layout will have the same number of grid layers in all realizations. Geomodel zones where the grid is defined as top conform or base conform may have varying number of grid layers from realization to realization if the geomodels structural model and grid also varies from realization to realization.
