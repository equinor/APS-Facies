---
title: global_master_config include file with APS parameters
---
APS can generate include file to be included in the FMU file `fmuconfig/input/global_master_config.yml`.

The generated file will be located in `fmuconfig/input` directory,
and it will have a name of the form: `<APS job name>_aps_params.yml`

The parameters included in the file are the parameters the user has selected (toggled on) in the APS GUI.

If there are multiple APS jobs having parameters to be included in the `global_master_config.yml` file,
they may be merged together first.

Note that the generated include files are not automatically included into the `global_master_config.yml` file since it is up to the user to decide which APS parameters to be updated or drawn by ERT.

The example shown here is a file generated by APS for the Valysar zone.

Note also that the include file is a YAML format file with keywords where the main keyword in the include file is the APS job name in capital letters and the sub-keywords are APS parameter names following a fixed naming convention.

For APS plugin to recognize the APS parameters the naming convention must be followed,
otherwise the parameter will be ignored by APS when APS plugin reads the `global_variables.yml` file that will be generated from the `global_master_config.yml` file when running ERT.

If the RMS project has multiple APS jobs in the same FMU project,
the APS job name keyword will distinguish between the parameters related to the different APS jobs.

The ERT parameter names (template parameter names) are also generated here by APS,
but it is up to the user to modify these names as long as they are unique within the ERT configuration.
But they must be consistent with the distribution file for GEN_KW if the APS parameters is to be drawn for initial ensemble by ERT or consistent with the parameter names used in `DESIGN_KW` if experimental design setup is used.

Example of a parameter file:

```yaml
# file: VALYSAR_aps-params.yml

# Note: Check that job name specified under keyword APS below is correct.
#       It should be the same as the APS job these parameters belongs to.
#       The job name must be used only once and the job name must be case insensitive
#       (e.g. Jobname and JOBNAME is treated as the same name).
# Note: This file can be renamed to aps_params.yml and included in the
#       fmuconfig/input/global master_config.yml file under the "global:" section
#       using the keyword and include statement:
#       APS: !include _aps_params.ymL

VALYSAR:
        APS_1_0_GF_GRF1_RESIDUAL_MAINRANGE:  2000.0 ~ <VALYSAR_APS_1_0_GF_GRF1_RESIDUAL_MAINRANGE>
        APS_1_0_GF_GRF1_RESIDUAL_PERPRANGE:   400.0 ~ <VALYSAR_APS_1_0_GF_GRF1_RESIDUAL_PERPRANGE>
        APS_1_0_GF_GRF1_RESIDUAL_VERTRANGE:     5.0 ~ <VALYSAR_APS_1_0_GF_GRF1_RESIDUAL_VERTRANGE>
        APS_1_0_GF_GRF1_RESIDUAL_AZIMUTHANGLE: 70.0 ~ <VALYSAR_APS_1_0_GF_GRF1_RESIDUAL_AZIMUTHANGLE>
        APS_1_0_GF_GRF2_RESIDUAL_MAINRANGE:  1000.0 ~ <VALYSAR_APS_1_0_GF_GRF2_RESIDUAL_MAINRANGE>
        APS_1_0_GF_GRF2_RESIDUAL_PERPRANGE:  1000.0 ~ <VALYSAR_APS_1_0_GF_GRF2_RESIDUAL_PERPRANGE>
        APS_1_0_GF_GRF2_RESIDUAL_VERTRANGE:     5.0 ~ <VALYSAR_APS_1_0_GF_GRF2_RESIDUAL_VERTRANGE>
        APS_1_0_GF_GRF2_RESIDUAL_AZIMUTHANGLE: 70.0 ~ <VALYSAR_APS_1_0_GF_GRF2_RESIDUAL_AZIMUTHANGLE>
        APS_1_0_GF_GRF3_RESIDUAL_MAINRANGE:  1000.0 ~ <VALYSAR_APS_1_0_GF_GRF3_RESIDUAL_MAINRANGE>
        APS_1_0_GF_GRF3_RESIDUAL_PERPRANGE:  1000.0 ~ <VALYSAR_APS_1_0_GF_GRF3_RESIDUAL_PERPRANGE>
        APS_1_0_GF_GRF3_RESIDUAL_VERTRANGE:     5.0 ~ <VALYSAR_APS_1_0_GF_GRF3_RESIDUAL_VERTRANGE>
        APS_1_0_GF_GRF3_RESIDUAL_AZIMUTHANGLE:  0.0 ~ <VALYSAR_APS_1_0_GF_GRF3_RESIDUAL_AZIMUTHANGLE>
```
